# MiaoDesk 产品愿景

- 状态:产品层最高说明,一切设计与实现以此为绳准
- 确立日期:2026-09-20；专业版目标修订:2026-10-03
- 确立人:项目所有者
- 定位:本文回答"这个产品是什么、用户感受到什么";具体设计与开发基线见 `DESIGN_BASELINE.md` 与 `DEVELOPMENT_ROADMAP.md`

## 一句话

**MiaoDesk 是一个漂亮的智能桌面。**

"漂亮"与"智能"都不是修辞,而是两条验收口径:漂亮指常驻桌面的视觉与动效质量,智能指桌面能理解并回应用户意图。两者都不通过"功能存在"来证明。

## 用户感知到的三个界面

用户不感知进程、模块或渲染后端。用户只感知到三个东西,全部设计都对照这三者展开。

### 一、搜索框

桌面顶部的常驻入口,一个框解决三件事:

```text
应用搜索
文件搜索
进入 AI 聊天的快速入口
```

它是"智能"的主要出口 —— 用户产生意图的第一个动作是打字,而不是打开某个应用。因此它的响应速度、命中准确度、以及从搜索无缝转入对话的路径,都是产品级指标,不是功能项。

### 二、动态桌面

壁纸是动态的,桌面上还有动态小组件。

```text
动态壁纸        载体 × 运行时：壁纸层承载 Scene（静态图 / 动态场景 / 视频）与 Web
动态小组件      玻璃时钟 / 今日待办 / 玻璃天气,以及未来的用户与 AI 内容
```

这是"漂亮"的主要载体,也是常驻资源占用的主战场。动效质量与低常驻资源在此直接冲突,冲突时的裁决规则见 `DESIGN_BASELINE.md` 第 2 节(Native C++ 与性能优先)。

### 三、DeepSeek Harness 专业工作台

独立的高级工作台,用户明确打开时才出现。它不属于常驻桌面路径,也不参与每帧渲染;它的存在不改变前两者的稳定性要求。

## 专业级完成目标（2026-10-03）

项目所有者进一步明确三个必达目标：

1. **动态壁纸达到 Wallpaper Engine 水平**：覆盖成熟作品所需的构图、动画、粒子、特效、音频/指针、播放、多屏和资源管理，并分阶段建设 3D、灯光、形变与程序化表现力。
2. **组件能力堪比 macOS 组件**：具备精致视觉、多尺寸布局、真实数据、直接操作、个性化、可访问性和低功耗，不止是三款固定样式。
3. **AI 创作达到专业级**：深入理解当前引擎、组件、数据和动作能力，能设计、制作、观察实际效果、评审修复并持续修改优秀作品。

壁纸与组件的底层能力、AI 可查询的能力知识和作品质量必须同步建设。每项新能力都应有公开内容表达、真实预览、优秀样例、创作规则和可复现评测。

详细能力、S0～S7 阶段和验收见 [PROFESSIONAL_DESKTOP_PLAN.md](PROFESSIONAL_DESKTOP_PLAN.md)。基础版稳定发布与完整专业目标分别验收；当前已有功能不能直接换算为扩展后目标的完成率。

## 设计基准

**所有功能都对照这三个界面来设计。**

判断一个新功能该不该做、做成什么样,问三个问题:它让搜索框更快更准吗?它让桌面更漂亮或更省资源吗?它让工作台更能干吗?三个都不沾的功能,不属于这个产品。

**当前已实现的大量具体细节,都是为这个总体设计服务的。** 源码目录、渲染后端、包契约、CI 门禁这些下层结构没有独立目标,它们的存在理由是支撑上面三个界面。当下层结构与上层体验冲突时,以下层让位于上层体验为准;但不得以破坏桌面稳定性为代价换取体验 —— 这条红线见 `DEVELOPMENT_ROADMAP.md` 结尾的门槛。

## 本愿景不覆盖的内容

为避免范围蔓延,以下明确不属于这三个界面:

- 旧式 Wallpaper / Scene / Widget Editor、Timeline、Inspector、Node Graph —— 已退出基线,不因"漂亮"或"智能"复活
- Web Widget 作为常驻默认组件 —— 已移除,不因"动态"回归
- 第三方内容直接获得 Windows API / 文件系统 / 注册表 / 原生 DLL 权限
- 逐项复制 Wallpaper Engine 编辑器 UI、专有格式或社区规模；动态表现力和运行质量的对标则正式纳入专业版

用户创作能力通过 Content Framework 重新立项,形态是 Parameter / Package tooling 与 Visual Creator,不是复活旧编辑器。
