# 黑客松十日谈：我们为什么想让 AI 真正住进桌面

> 可作为 CSDN / 知乎文章草稿，发布后把文章 URL 提交比赛表单。

## 第一天：问题不是“再做一个聊天框”

最开始我们想做的事情很简单：既然电脑已经可以运行很强的 AI，为什么用户还需要打开一个网页、复制内容、切换窗口，再手动完成最后一步？

我们真正想要的是：AI 就在桌面里。

它应该知道用户现在是想找一个文件、打开一个应用、换一张壁纸，还是做一个新的桌面组件。

所以 MiaoDesk 的第一个决定，就是不把 AI 做成一个孤立的聊天页面。

## 第二天：先把桌面做好

如果桌面本身不稳定，AI 再聪明也没有意义。

我们先把产品拆成最基本的三个界面：

- 搜索；
- 动态桌面；
- AI。

搜索负责最快的入口，动态桌面负责长期存在的视觉和信息，AI 负责理解复杂需求。

这也决定了后面的技术路线：常驻功能优先 Native C++，而不是让整个桌面都依赖浏览器。

## 第三天：AI 不能拥有无限权限

让模型直接执行 Shell 命令当然很方便，但这不是我们想交给普通用户的产品。

我们更希望 AI 像一个被严格授权的员工。

它可以：

- 搜索；
- 创建内容；
- 校验内容；
- 预览内容。

但每一个能力都由产品提供明确工具。

这样模型负责思考，软件负责执行。

## 第四天：把规则写成 Skills

很快我们遇到另一个问题：壁纸规则越来越多，Widget 规则也越来越多。

如果全部写进 System Prompt，Prompt 会越来越长，而且任何一次修改都有可能影响其他任务。

于是我们把规则拆成 Skill：

- Content Package Basics；
- Wallpaper Content；
- Widget Content；
- Content Review。

它们都是普通 Markdown 文件。

这件事看起来很简单，但它让 Agent 终于有了一套可以版本管理、可以审查、也可以被其他 AI 读取的“操作手册”。

## 第五天：AI 生成的不是代码，而是内容

我们不希望一句“帮我做壁纸”最后变成一段不透明脚本。

所以 MiaoDesk 定义了自己的 Content Package。

AI 输出的是 JSON：

- manifest；
- parameters；
- scene。

动态效果、文字、粒子、数据绑定都由 Runtime 解释执行。

这意味着内容可以在应用前检查，也可以明确限制资源、能力和性能。

## 第六天：DGX Spark 让本地 AI 真正可用

桌面 Agent 和普通聊天不一样。

它可能需要更长的上下文，需要连续调用多个工具，也可能长时间运行。

如果每一步都依赖公网，桌面 AI 很难真正变成系统的一部分。

DGX Spark 给了我们另一种选择：把大模型直接放到用户附近。

MiaoDesk 通过 OpenAI Compatible 接口连接 DGX Spark 上的 vLLM。对于 Windows 客户端来说，本地模型和云模型只是不同的 API Profile。

## 第七天：一个模型不应该承担所有事情

我们很快发现，没有必要让最大的模型处理所有任务。

简单搜索和轻量任务可以用小模型。

复杂 Agent 规划可以用更强模型。

图片生成又是另一条独立链路。

所以架构从“一个 AI”变成了“多个 Provider + 多个模型 + 按窗口选择”。

本地 DGX Spark、StepFun 或其他 OpenAI Compatible 服务可以同时存在。

## 第八天：真正难的是最后 20%

能跑起来不等于能交付。

窗口层级、不同 DPI、多显示器、ARM64、安装器、文件搜索服务、卸载残留……这些问题往往和模型本身毫无关系，却直接决定用户觉得产品是否可靠。

我们开始把越来越多真实问题变成自动测试。

例如：

- AI 创作窗口必须真的可见；
- ARM64 二进制必须检查 PE Machine；
- 安装器必须真的安装、再真的卸载；
- 文件搜索不能只检查服务状态，而要真的创建一个文件并搜出来。

## 第九天：本地 AI 的意义不是“离线”

我们最初把本地模型的价值理解成隐私和离线。

后来发现更重要的是“可控”。

模型、上下文、推理服务和桌面工具都在自己的体系里，就可以根据不同任务设计不同策略。

AI 不再只是一个远程 API，而开始变成产品 Runtime 的一部分。

## 第十天：我们想做的是 AI Native Desktop

十天以后，MiaoDesk 仍然不是一个完成的终点。

但我们已经验证了最重要的链路：

```text
用户自然语言
 → Agent
 → Skills
 → Native Tools
 → Content Package
 → Preview
 → 用户确认
 → Windows Desktop
```

DGX Spark 则让这条链路中的“智能”可以真正运行在用户附近。

我们对 AI PC 的理解也发生了变化。

AI PC 不应该只意味着“电脑里有一块 NPU”或者“系统里多一个聊天按钮”。

真正的 AI Native PC 应该让模型拥有明确的工具、规则、安全边界和持续存在的交互空间。

桌面，就是最自然的起点。
