## 1. 最终交付目标

交付一个用户愿意每天常驻运行的 Windows 智能桌面：搜索快且可靠；动态壁纸具有成熟动态壁纸产品的表现力；组件兼具精致视觉、真实数据、实用交互与低功耗；AI 能完成从需求到可维护成品的专业创作。

三个新目标是产品完成条件：

| 目标 | 必须交付 | 不足以证明完成 |
| --- | --- | --- |
| Wallpaper Engine 级壁纸 | 2D/2.5D、粒子、动画、音频/指针、后处理、视频/Web、多屏、电源策略，以及后续 3D/灯光/形变的作品与测量 | 贴图位移；仅有枚举/序列化；单张截图 |
| macOS 级组件 | 浏览安装、多尺寸、自适应布局、数据更新、直接操作、状态反馈、键盘/无障碍、个性化和低功耗 | 三款固定卡片；假数据；只模仿玻璃外观 |
| 专业 AI 创作 | 设计、素材、制作、校验、真实渲染、评审、局部修复、连续修改和交付 | 仅生成合法 JSON；模型自称好看；封面冒充动画验收 |

使用 MiaoDesk 自己的格式、Native Runtime 和创作流程。旧大型编辑器的代码和 UI 不自动复活；但 3D、形变、程序化效果等表达能力不能再以“旧编辑器特性”为由排除。Steam Workshop 生态规模、Apple 跨设备私有协议不作为本轮完成条件。

完整专业版必须满足 S0～S7。S1 后可按原 RC 规则交付稳定基础版，但只能标注实际范围，不能宣称三个新目标已经完成。

## 3. 壁纸基础能力

外部依据见 [Wallpaper Engine 对标](WALLPAPER_ENGINE_BENCHMARK.md)。下表是 MiaoDesk 建设要求。

| 能力组 | 基础能力 | 代表作品与验收 | 任务 |
| --- | --- | --- | --- |
| 素材/构图 | 图层、变换、锚点、裁切、遮罩、混合、透明度、色彩、文字/矢量、素材参数化 | 横屏/超宽/竖屏；主体与图标可读区正确 | WALL-01 |
| 2.5D/局部动态 | 分层视差、深度图、风/水/呼吸/局部扭曲、强度/速度参数 | 深度风景、植被水面、人物局部动态；无破边与跳变 | WALL-02 |
| 动画/行为 | 关键帧、曲线、循环、事件、状态转换、确定性随机、平滑参数过渡 | 昼夜切换、事件触发、循环接缝与暂停恢复 | WALL-03 |
| 粒子/后处理 | 发射、寿命、力、碰撞子集、纹理动画、多 Pass、Bloom/模糊/折射/色调、资源预算 | 雨雪、萤火、星尘、霓虹反射；组合效果 | WALL-04 |
| 输入/媒体 | 指针归属、频谱/节拍、响应曲线、设备恢复、受控媒体信息 Provider | 静音、拔设备、跨屏不会误响应 | DESK-03～05、WALL-05 |
| 播放/宿主 | 图片/视频/Web/Scene 生命周期、逐屏/跨屏、质量档、全屏/锁屏/省电策略 | 多屏持续运行、视频循环、游戏前后台 | WALL-06、P0、PERF |
| 高级表现力 | 3D 网格/相机/材质/灯光/雾、骨骼/形变/受限物理、程序化视觉 | 3D 光照场景、可动角色、交互形变、程序化效果 | ADV-01～04 |

每项能力同时交付：运行时、schema/参数、预览/桌面一致性、资源预算、最小与组合示例、AI 使用知识和回归证据。仅增加渲染代码不能关闭任务。

图像与视频需明确 SDR/HDR、色彩空间和透明度处理的支持矩阵；未支持模式不能静默改变颜色。D2D/D3D11 支持差异必须对作者可见；按能力选择后端，缺后端时明确说明可选择的降级，不静默丢效果。GPU device loss、坏 Shader、坏素材必须有隔离与恢复路径。

## 4. 组件基础能力

对标与 Windows 适配见 [macOS 组件对标](MACOS_WIDGET_BENCHMARK.md)。目标是可组合的平台，官方组件是同一平台上的作品。

### 4.1 布局、绘制和交互

- Definition 声明小/中/大等尺寸族；支持行列、对齐、间距、内边距、尺寸约束和溢出规则。
- 提供文字、图片、图标、进度、列表、简单图表、按钮/开关等 Native 原语；长中文、不同字体、空态与错误态有规则。
- 区分控件命中和拖动区域，避免点待办却拖走组件；保留 Widget > Icons > Wallpaper 与 geometry 保护。
- 城市、时区、列表、数据来源和主题可配置；同包多实例互不覆盖。
- 提供焦点、键盘、屏幕阅读器语义、高对比度、减少动态效果。

### 4.2 数据、动作和更新

- Provider 统一快照、时间戳、有效期、加载/离线/错误状态与变更通知；网络/解码不进入绘制线程。
- 采用事件、更新计划和失效通知；Clock 按所需时间边界刷新，Tasks 在数据变更时刷新，Weather 使用缓存与有界重试。
- 动作经宿主注册表执行：完成待办、计时、媒体控制、打开应用/详情；结果有反馈，重复操作幂等，失败可恢复。
- 日历、媒体、系统状态、用户选定文件/照片和外部数据逐项接入正式 Provider；读权限与动作权限分别描述，撤销立即生效。
- AI 只能选择当前目录内真实存在的 Provider/Action；新增 binding ID 不会创造宿主能力。先交付连接器，再开放创作。

### 4.3 官方参考套件

专业版至少 8 类：时钟、天气、待办、日历议程、计时/专注、媒体、照片、系统状态。每类至少两个适用尺寸，宣称的交互/数据来源真实可用。日历可先支持用户导入数据；远端同步单列，不能把导入称为双向同步。

参考套件验证官方、用户和 AI 使用相同能力。必须依靠官方专用 painter 才成立的效果要登记框架缺口，不用特例掩盖。

## 5. AI 深入理解与使用底层能力

### 5.1 真实能力目录

规划新增能力目录，复用现有 Creator registry 和内容契约；格式在 CAP-01 冻结，不视为已上线 API。

每条包含稳定 ID、版本、类型/单位/范围、默认值、后端、载体、数据/动作权限、资源限制、预览支持、组合限制、正反例、错误诊断、性能建议和验证证据。

必须区分：模型可声明、运行时可执行、预览可展示、AI 可创作、真机已验收。安装版本、设备/后端与 Provider 可用性共同决定本次可用集合。以运行时注册信息生成机器目录与作者文档，避免三份手抄能力表。

### 5.2 按创作阶段检索知识

| 层 | 内容 | 用途 |
| --- | --- | --- |
| 基础契约 | 包、参数、单位、坐标、资产、层级、生命周期 | 制作与校验 |
| 能力卡 | 支持/限制、后端、资源成本、最小声明式示例 | 选型与组合 |
| 创作配方 | 雨夜、水面、音频、视差、议程、媒体、交互待办 | 需求转设计 |
| 参考作品 | brief、源包、参数、真实帧、性能、设计说明、修改点 | 学习构图与节奏 |
| 失败样本 | 症状、诊断、根因、修复前后、回归 | 定向修复 |

按需读取现有 Skills，记录检索条目与版本以便复现。示例库与保留评测集分离；知识质量通过“能生成、能组合、能修改”验证，不能仅统计文档长度。

### 5.3 专业制作闭环

1. 需求与设计：确定风格、情绪、构图、动态、尺寸、交互、数据与预算；只询问影响交付的缺失条件。
2. 能力规划：需求映射为当前支持的能力组合；核查依赖，明确未支持需求，不静默省略。
3. 素材准备：导入/生成背景、分层、遮罩、深度、粒子图集；检查分辨率、透明边缘、引用和来源。
4. 制作调参：产出可读、参数化、可继续修改的包；组合效果保持统一风格与时间节奏。
5. 确定性校验：真实 validator 检查结构、资源、能力、参数、预算，定位到文件/节点/属性。
6. 运行观察：目标后端采样多时间/比例/数据状态，运行交互脚本与测量；图像必须真正进入视觉 Provider 请求。
7. 评审修复：按需求、真实帧和测量定位缺陷；有界迭代，保留上一有效候选。
8. 交付续改：用户预览、调参、显式应用与恢复；“换颜色/小一点/保留布局”能做正确的局部修改。

复用 CCA 的候选摘要、预算、取消、事务与恢复，不另造第二套 Agent 引擎。初始沿用最多 2 次自动修复、10 分钟制作预算；变更需评测依据，超时可由用户发起继续。

### 5.4 能力与 AI 同步交付

新能力进入 Creator 前同步交付目录、规则/样例、工具、校验、预览、真实作品和评测。旧包继续运行或显式迁移；后端/Provider 失效时重新规划受影响部分。

默认 AI 产物仍是声明式内容与受控素材。高级 Shader 创作由 ADV-04 单独实施，需同步修改源码限制、Skill、校验、ABI、编译/资源限制和隔离；本规划不把尚未开放的 HLSL/脚本写成当前工具能力。交互先用有界行为图，通用脚本 VM 不作为首选实现。

## 7. 专业级验收

下列是初始目标，尚无达标结论。PRO-03 固定硬件/样本后登记测量基线。门槛变更必须写原因、证据和影响，不能为让当前版本通过而静默放宽。

### 7.1 固定样本与对照

- S3 壁纸 12 场景：分层风景、雨夜霓虹、水面、植被、人物局部动态、星空粒子、音乐可视化、鼠标交互、视频循环、Web 交互、多屏全景、复合特效。S6 另加真实 3D、骨骼/形变、受限物理、程序化视觉四类高级场景。
- 记录 brief、素材来源、复杂度、参数、包摘要、后端、预期行为、比例与资源档。WE 使用合法素材制作等价场景，记录其版本/设置；不同复杂度不能用于性能优劣结论。
- 组件采用 8 类套件，覆盖适用尺寸和加载/正常/空/离线/错误/长文本/权限撤销；macOS 比任务完成与体验，不跨平台硬比 CPU 百分比。
- AI 开发集至少 30 壁纸+30 组件；另保留 10+10 个不进入示例库的任务，每项独立 3 次。每领域至少 5 个多能力组合、5 个连续修改任务，可与主题交叉。

### 7.2 创作质量门

| 指标 | 初始目标 | 测量 |
| --- | --- | --- |
| 结构/资源有效 | 预算内最终有效率 ≥95% | validator+实际加载；超时/失败不能从分母删除 |
| 用户任务成功 | 两领域分别 ≥90% | 逐条需求验收，缺核心效果/假交互计失败 |
| 连续修改成功 | ≥90% | 修改正确，要求保留部分未被破坏 |
| 虚构能力 | 放行集 0 次 | binding/Action/效果对实际目录 |
| 视觉/体验 | 每领域平均 ≥4/5；作品关键维度均 ≥3/5 | 至少两位评审盲评，分歧 >1 分复核 |
| 对标 | 每类中位评分不低于等价参考 | 随机顺序、隐藏来源；弱类不能被整体均分掩盖 |
| 应用/恢复 | 固定故障集 100% 前态正确 | 取消、超时、坏包、重启、重复/迟到操作 |

视觉维度：构图层次、风格一致、动效节奏/循环、可读性/可用性、需求符合度。组件的真实数据/交互、壁纸的持续播放/图标可读性/资源档是硬门。模型评审辅助定位，最终人工签收不可由模型自评替代。

评分报告同时保留成功数/总数、每题结果和独立重复次数；小样本通过只代表该固定集，后续继续积累真实失败样本。记录生成/修复/渲染/评审各段 p50/p95、token/图像费用、重试数。默认总制作上限 10 分钟；费用阈值在实际 Provider 测量后冻结，未测量不承诺低成本。

### 7.3 运行与性能门

- 至少 x64 与 ARM64 各一台实机；1366×768、1080p、1440p/4K，100/150/200% DPI，双屏、竖屏、跨 DPI。
- 既有四场景用现有采集器：预热后 30 秒×3；复杂内容增加 10 分钟和 2 小时测试；专业版增加 8 小时桌面长稳。
- 指定设备/内容下，30 fps 档 frame-time p95 ≤1000/30 ms，60 fps 档 ≤1000/60 ms；分别报告实际丢帧/卡顿，达不到时显式降档。
- 固定场景 CPU、内存、句柄、线程、GPU、帧时相对已签收基线回退 >10% 必须解释和处理；GPU 不可测标未测，不记零。
- 三个事件/静态组件在无数据和交互变化的 60 秒内无无效内容重绘；compositor re-present 单列。Clock 按显示精度刷新，分钟/秒钟样式分开。
- 暂停/隐藏/锁屏后的绘制、采集、轮询符合公开策略；停止模式释放对应资源；恢复无旧帧、重复订阅或突发刷新。
- 长稳使用预热后同状态资源曲线，无无法解释的单调增长；重复开关回到同状态后资源稳定。

### 7.4 证据与发布

沿用五条同 SHA CI 和 RC evidence；增加能力矩阵、作品录像/帧、原始评分、交互结果、性能、模型/Skill/能力版本、限制和迁移报告。绑定候选 SHA、包摘要、设备、OS、驱动和工具版本，日志脱敏。

## 8. 实施节奏与分工

以“能力→包→预览→桌面→AI→作品→证据”的纵向切片推进，跨多个切片的大任务先拆子项。建议 1～2 周一个迭代，以出口而非日历判完成；S0 评估后再给里程碑日期。3D/形变/隔离、外部数据、多模态质量先做技术探针，不用本规划推算确定完工日。

责任角色：桌面/发布维护者负责 S1；渲染维护者负责 WALL/ADV；组件维护者负责 WPRO；Creator 维护者负责 CAP/AIP；产品/视觉与 Windows 验收者负责签收。角色可以由同一开发者承担，领取时写真实负责人。

高风险项采用可验证探针：3D 格式/动画导入、GPU 隔离、复杂素材准备、第三方数据授权和多模态质量分别先验证一条端到端作品路径；探针失败登记具体限制和替代实现，不能自行删除必达目标。隔离优先复用当前正式 EXE 的受控子进程角色，确需改变 build graph 时同步架构与打包契约。

每轮先修用户阻塞与回退。S1 之后主要建设投入转向 WALL/WPRO/CAP/AIP；能力与 AI 同步交付。缺设备时推进独立实现/契约/自动测试，真机阶段仍待签收。

## 9. 首批推进顺序

1. PRO-01 核实已有实现与证据；PRO-02/03 准备对标样本、环境和预算。
2. P0-03/04 完成壁纸/组件 20 次生命周期的自动部分并排入真机验收。
3. P0-07/08/09 完成重启恢复、强杀清理、升级安全，同步 UX/PERF 签收。
4. CAP-01/02 先使 AI 准确理解已有引擎，交付可查询目录与首批样例。
